# 双格式导出契约

## 输入

- 一个 `10_项目/<日期_主题>/` 内的 UTF-8 Markdown 长文。
- 第一处一级标题作为文章标题。
- 图片必须已经上传图床，并写成 `![说明](https://...)`。
- 输入内容视为定稿；导出过程只改格式，不改内容。

## 公众号文件

命名：

```text
36_公众号mdnice_<主题>.md
```

必须满足：

- 保留一级、二级、三级标题，粗体、斜体、引用、列表与链接。
- 保留图片在正文中的原始顺序。
- 图片只允许 `https://`。
- 删除文件头 frontmatter、HTML 注释、独立水平线。
- 不加入备用标题、操作说明、发布建议或图片清单。

## X Article 文件

命名：

```text
37_XArticle_<主题>_富文本粘贴版.html
```

必须满足：

- UTF-8 单文件 HTML，可直接在 Chrome 打开。
- 正文位于独立的复制区域，操作说明不得进入复制内容。
- 提供“复制富文本”按钮，同时写入 `text/html` 与 `text/plain`。
- 使用原始 HTTPS 图片地址，不下载、不转存、不改图。
- 段落保持短而清晰，但不重写原文。

## 图片规则

| 输入 | 处理 |
|---|---|
| `![alt](https://...)` | 接受并保留 |
| `![alt](http://...)` | 拒绝，要求 HTTPS |
| `![[image.png]]` | 拒绝，列出本地引用 |
| `![alt](./image.png)` | 拒绝，列出本地引用 |
| `![alt](/absolute/image.png)` | 拒绝，列出本地引用 |
| `[截图位]`、`【配图待补】` | 拒绝，要求先完成母版 |

脚本只做语法校验，不保证远程服务器始终可访问。需要联网验证时，应单独检查 URL，不因临时网络失败覆盖已有输出。

## X 平台边界

X Articles 支持富文本和图片，但平台没有保证会把外部 HTML 中的远程图片自动转存为平台媒体。HTML 输出应尽最大可能保留图片节点；如果粘贴后图片缺失，只能改为逐图上传或另行使用浏览器自动化。不要把这个平台限制伪装成导出成功。
