# 双格式导出契约

## 输入

- 一个 `10_项目/<日期_主题>/` 内的 UTF-8 Markdown 长文。
- 第一处一级标题作为文章标题；没有一级标题时必须通过 `--title` 补入。
- 图片必须已经上传 MDNice 图床；本地图片通过 `--image-map` 转换成 `![说明](https://...)`。
- 输入内容视为定稿；导出过程只改格式，不改内容。

## 公众号文件

命名：

```text
36_公众号mdnice_<主题>.md
```

必须满足：

- 保留一级、二级、三级标题，粗体、斜体、引用、列表与链接。
- 保留图片在正文中的原始顺序。
- 图片只允许 `https://`。
- 删除文件头 frontmatter、HTML 注释、独立水平线。
- 不加入备用标题、操作说明、发布建议或图片清单。

## X Article 文件

命名：

```text
37_XArticle_<主题>_富文本粘贴版.html
```

必须满足：

- UTF-8 单文件 HTML，可直接在 Chrome 打开。
- 正文位于独立的复制区域，操作说明不得进入复制内容。
- 提供“复制富文本”按钮，同时写入 `text/html` 与 `text/plain`。
- 使用原始 HTTPS 图片地址，不下载、不转存、不改图。
- 段落保持短而清晰，但不重写原文。

## 图片规则

| 输入 | 处理 |
|---|---|
| `![alt](https://...)` | 接受并保留 |
| `![alt](http://...)` | 拒绝，要求 HTTPS |
| `![[image.png]]` | 有 HTTPS 映射则替换，否则拒绝 |
| `![alt](./image.png)` | 有 HTTPS 映射则替换，否则拒绝 |
| `![alt](/absolute/image.png)` | 有 HTTPS 映射则替换，否则拒绝 |
| `[截图位]`、`【配图待补】` | 拒绝，要求先完成母版 |

脚本只做语法校验，不保证远程服务器始终可访问。需要联网验证时，应单独检查 URL，不因临时网络失败覆盖已有输出。

## MDNice 图床流程

1. 只上传母版实际引用的原图，不上传文章正文。
2. 上传目标必须是 MDNice 当前选择的图床，不得使用 GitHub 仓库代替。
3. 每张图片上传成功后，记录 MDNice 返回的 HTTPS 地址和准确 alt 文本。
4. 图片映射 JSON 是一次性运行数据，放在 Git 仓库之外，不提交版本库。
5. 只有全部图片都有可确认的 HTTPS 地址时才执行导出；任一图片失败则整篇停止。

`YangWW-Explorer/article-fenfa` 的版本管理边界仅包含 Skill 自身：

- `SKILL.md`
- `agents/`
- `references/`
- `scripts/`

禁止提交母版文章、附件图片、图片映射 JSON、公众号输出和 X Article 输出。

## 标题规则

- 已有一级标题时保留，不重复添加。
- 没有一级标题时优先使用 `--title`。
- 补标题后，如果正文最低标题从 `###` 或更深层级开始，整体上移到最低层级为 `##`。
- 不改变标题文字，不根据正文杜撰标题。

## X 平台边界

X Articles 支持富文本和图片，但平台没有保证会把外部 HTML 中的远程图片自动转存为平台媒体。HTML 输出应尽最大可能保留图片节点；如果粘贴后图片缺失，只能改为逐图上传或另行使用浏览器自动化。不要把这个平台限制伪装成导出成功。
